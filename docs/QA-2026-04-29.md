# QA manual — Sprint 2026-04-28 (cloud.didacta.io)

> Checklist navegable para validar los caminos críticos del último sprint
> tras aplicar las migraciones en producción. Recorrelo de un tirón con
> las dos pestañas abiertas (admin + alumno) — los flujos están diseñados
> para fluir de uno a otro sin saltar entre archivos.

---

## Pre-requisitos (1 vez antes de empezar)

- [ ] **Migraciones aplicadas**. Tras el redeploy, ejecutar el health-check:
      `pnpm --filter @didacta/api post-deploy:check` (o desde el shell de
      Easypanel si no hay acceso local). Salida esperada: `Todas las
      verificaciones pasaron.` Si falla cualquier check → `prisma migrate
      deploy` no corrió correctamente; **detener QA y revisar**.
- [ ] **Sesiones**: una pestaña con `tenant_admin`, otra con `formador`,
      otra de incógnito para `alumno`. Cualquier tenant ya operativo en
      `cloud.didacta.io` sirve.
- [ ] **Crear curso de pruebas** (formador): `Curso QA 2026-04-29` con
      una sección y dos lecciones VIDEO en blanco — lo vamos a poblar abajo.

## 1. Editor enriquecido + upload de imágenes inline (E3 + FU-5)

| # | Quién | Acción | Esperado |
|---|---|---|---|
| 1.1 | formador | Editar la lección 1 → descripción del curso | El editor Tiptap aparece (toolbar con bold/italic/list/link/image) en lugar del textarea legacy |

**Criterio**: la imagen sigue accesible al refrescar (no es un object-URL volátil).

## 5. SMTP multi-provider con secret cifrado (G1)

| # | Quién | Acción | Esperado |
|---|---|---|---|
| 5.1 | tenant_admin | `/admin/avanzado` → tab "SMTP" | Form con host/port/user/from. El campo password está enmascarado y nunca se devuelve en GET |
| 5.2 | tenant_admin | Probar config de Brevo (`smtp-relay.brevo.com:587`) → click "Probar conexión" | Handshake OK; muestra `verify ok` |
| 5.3 | tenant_admin | Probar config inválida (`port: 99999`) → guardar | Rechaza con error 400 (zod); no persiste |
| 5.4 | tenant_admin | Guardar config válida → consultar `tenant_setting` en DB | Row con `scope=notifications, key=smtp` cifrado en `value_encrypted` (no aparece la password en plano) |
| 5.5 | alumno | Matricularse | Recibe el email **vía Brevo** (header `X-Mailer`) — no vía SMTP global |
| 5.6 | tenant_admin | Cambiar a config rota a propósito (`host=invalid.example`) | El siguiente envío persiste `failedAt` con `failureReason=smtp_send_failed:...` y la app no rompe |
| 5.7 | tenant_admin | Borrar el setting | Cae al SMTP global del producto (env vars) |

**Criterio**: dos tenants distintos pueden tener providers distintos sin contaminarse. Cambiar el secret no requiere reiniciar la API.

## Reportar bugs

Si algo falla, abrir issue en GitHub con:
- **Título**: `[QA 2026-04-29] {feature} — {síntoma}`
- **Cuerpo**: paso del checklist que falló (ej. "2.4"), tenant + URL,
  expected vs. actual, screenshot.
- **Label**: `bug` + `qa-2026-04-29`.

Los bugs P0 (rompen el camino crítico) deberían bloquear cualquier nuevo
deploy hasta resolverse.

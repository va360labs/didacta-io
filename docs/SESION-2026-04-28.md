## Follow-ups documentados (no incluidos)

Lista de cosas que dejé fuera de scope a propósito; cada una lista por
qué se difirió y qué requeriría:

1. **Multi-categoría con pivote N:N** (E2 actual es 1:N). Necesita
   migración de `mod_courses_course_category(courseId, categoryId)`,
   cambios en filtro del catálogo, UI multi-select en builder.
2. **Wiring runtime de storage para EvidenceVault, ThemingService,
   SCORM upload**. FU-4 sólo migró `StorageController`. Para los
   demás servicios hay que pasar `tenantId` hasta esos servicios.
3. **Invalidación cross-instancia del cache de storage**. Si la API
   corre en >1 pod, cada uno cachea aparte. Easypanel actual usa 1
   instancia, no urge.
4. **Envío SMTP asíncrono dedicado vía BullMQ**. Las notificaciones ya
   van a través del outbox + handlers async, así que no bloquean la
   request HTTP. Backpressure SMTP per-tenant cuando haya volumen real.
5. **AWS SES vía AWS SDK** (no SMTP relay). SES via SMTP es funcional;
   SDK nativo añade dependencia sin beneficio inmediato.
6. **Drag & drop para reordenar lecciones** (existe parcialmente con
   dnd-kit, pero el comentario en `course-editor.tsx` menciona que
   hay edge cases pendientes).

### Convenciones que se mantuvieron toda la sesión

- Cada item del feedback → 1 PR conventional commits, sin
  `Co-Authored-By` ni atribución a IA.
- Permiso explícito en sesión para `--no-verify` por bug pre-commit
  hook en Windows (lint-staged no resuelve).
- `corepack pnpm` (10.21.0) en lugar de pnpm directo.
- Branches: `feat/`, `fix/`, `chore/`, `docs/`.
- Cada PR documenta lo que NO incluye en una sección "follow-up".
- `docs/mejoras.md` se marca con `[x]` y número de PR al cerrar cada
  item en el mismo commit, no antes.

  se actualiza a Estado=Hecho al cerrar cada PR.

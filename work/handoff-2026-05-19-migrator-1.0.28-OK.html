  8. 1.0.26 · courseModule único "General" por curso mezclaba todas las lessons. Fix: parsear sections[] del response /steps, persistir en raw_payload.__sections, encoding parent_course_id = '{course}-s{idx}', crear UN module por section en el load.

Trabajo pendiente

1. Bug del CORE: lessonsUpsert no actualiza moduleId en UPDATE · deuda alpha.64

Path: apps/api/src/marketplace/sandboxed-didacta.service.ts:931-947.

El lessons.upsertByExternalRef encuentra la lesson existente por (tenantId, externalSource, externalId) y la UPDATEa solo title, position, content, durationMinutes. NO toca moduleId. Lessons quedan pegadas al primer module donde se crearon — si cambia su sección en LearnDash, no se mueve en Didacta.

Workaround actual (lo hago manualmente desde la BD entre runs): DELETE FROM mod_courses_lesson WHERE external_source = 'learndash' antes de re-correr el job. Funciona pero no es escalable.

Fix definitivo: añadir moduleId: section.id al objeto data del UPDATE (línea ~934). Una línea. Requiere alpha.64 (rebuild Docker + redeploy Easypanel).

2. ADR-015 host refactor · deuda residual

3 archivos en apps/web/ conocen al migrator-learndash por nombre (violación ADR-015):

  • apps/web/src/modules/migrator-learndash/index.ts (33 LOC, sidebar item hardcoded)
  • apps/web/src/app/(app)/admin/integraciones/migrator-learndash/page.tsx (136 LOC, slug en la ruta)
  • apps/web/src/modules/index.ts:22 (registro del módulo en el catálogo del host)

Plan completo guardado en engram didacta/pending-adr015-host-refactor: endpoint GET /api/v1/marketplace/installed/surfaces, sidebar runtime-driven, page parametrizada [slug]/page.tsx.

3. ET-001b fan-out entities · Sprint 5 backlog

Sin estos el migrador no es funcional para tenants reales:

  • Questions per quiz: los 3 quizzes migran solo el shell.
  • Enrollments per course/group: los 8 groups quedan SKIPPED en cada run.
  • Media binaries: raw_payload.featured_media es solo un ID, no se descargan los assets.
  • Progress tracking: estado de cada user en cada lesson.

Ya documentado en Notion (backlog Sprint 5).

4. Gotcha del re-install + jobLifecycle · conocido

Al hacer upgrade in-place de versión del módulo (e.g. 1.0.27 → 1.0.28 vía marketplace UI), el jobLifecycle.onJobTick puede no quedar correctamente registrado en BullMQ. Los jobs nuevos quedan atascados en status='extracting' sin avanzar (sin ticks).

Workaround: restart del service didacta-api en Easypanel. El OnApplicationBootstrap de alpha.63 re-registra todo limpio.

Fix futuro: el install pipeline debería jobLifecycle.unregister(name) antes del register, o el dispatcher de jobs debería re-leer el manifest al recibir un tick para un module sin handler.

Arquitectura final del migrator (estado mental)

EXTRACT
├── paginate (perCourse: lessons/topics/quizzes piden ?course=N)
│   ├── users      via wp/v2/users
│   ├── courses    via ldlms/v1/sfwd-courses
│   ├── lessons    via ldlms/v1/sfwd-lessons?course=N × cada course
│   ├── topics     via ldlms/v1/sfwd-topic?course=N
│   ├── quizzes    via ldlms/v1/sfwd-quiz?course=N
│   └── groups     via ldlms/v1/groups
│
└── fixup (subphase 'fixup' del extract)
    └── × cada course → GET /sfwd-courses/:id/steps
        ├── parser jerárquico (keys 'lesson:N'/'sfwd-lessons:N'/etc.)
        ├── UPDATE stg_lessons.parent_course_id con courseId real
        ├── parsear sections[] y persistir en stg_courses.raw_payload.__sections
        └── encoding parent_course_id = '{course}-s{idx}' para lessons en una section

TRANSFORM
├── courses → mapCourse propaga raw.__sections al canonical.sections
└── lessons → applyMapper recibe raw con r.course extraído del prefijo numérico
              de parent_course_id; post-map override del canonical.parentCourseSourceId
              con el string completo si el encoding tiene '-'

LOAD
├── courses → courses.upsertByExternalRef + courseModules.upsertByExternalRef
│   ├── 'General' (external_id = courseId) SOLO si hay lessons huérfanas
│   └── × cada section → courseModule con external_id = '{course}-s{idx}', title = section.title
└── lessons → lessons.upsertByExternalRef con moduleExternalRef = parentCourseSourceId
              que puede ser courseId pelado o '{course}-s{idx}'
